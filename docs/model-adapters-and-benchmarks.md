# Model adapters and comparable evidence

Observatory starts with Jev; it is not intended to be a Jev-only benchmark. Keep the current brand and wire formats compatible while separating model behavior from experiment orchestration.

## Current implementation

Hosted execution depends on an injected execution port: compile, reservation, infer, assess, cost, report and describe. The composition root selects the reviewed Jev adapter. That adapter owns the native compiler, response validation, frozen tariff and report contract. The service owns account isolation, immutable storage, paid authorization, dispatch claims and settlement. Browser requests cannot choose arbitrary endpoints, executable code or adapters. A test-only second implementation verifies a different response shape and input-plus-output billing.

New saved runs bind the adapter ID/version alongside the immutable plan; resume rejects an incompatible adapter. Pre-adapter hosted plans are explicitly recognized only by the Jev adapter. Existing request bytes, plan hashes, policies and historical observations are unchanged. A price, renderer or response-contract change requires a new version with its own compatibility review. Preserve old adapters for inspection/resumption; never reinterpret an old reservation under a new tariff.

Policy composition is conceptually independent of the model, but the current workbench renderer and advisory requests emit Jev native primitives. They do not yet execute arbitrary models. A new adapter must compile the same policy semantics to that provider's supported request format, declare unsupported semantics and validate its response. JSON generated by another LLM is not a native probability distribution; missing probabilities remain missing. Advice and test execution are separate capabilities and should be independently selectable when more adapters exist.

Community bundles already accept arbitrary model identifiers and hash their policy document and suite. The historical `jev-observatory-bundle` format name is a compatibility identifier, not a model restriction. User-uploaded evidence is not independently authenticated. Hosted execution is also not a provider-signed attestation.

## Provenance and comparison requirements

Bind each run to the policy snapshot/hash, compiler/renderer and adapter versions, catalog/suite hash, planner seed/options, application context, frozen request hashes, actual reported model identity, responses and usage. Imported reports must preserve recorded policy identity rather than substitute the current draft. Legacy runs with multiple contracts need their per-condition identities; never fabricate a single shared policy version.

Before building a cross-model leaderboard, add an explicit optional measurement schema: currency and tariff/version/date; provider-billed input/output/cache/reasoning units where available; latency boundary, concurrency, retries and cold/warm status; model revision, quantization, runtime and hardware for local models. Unknown cost is null, not zero. Free inference does not imply zero hardware/energy cost. Compare full pipeline costs, including advice, second passes and judges, separately from per-request inference.

Report false-negative and false-positive rates with their separate denominators, abstentions, invalid/unavailable results, severity and confidence intervals. Keep thresholds application-specific and selected on development data before held-out evaluation. Show a cost/latency/error tradeoff rather than a single universal winner. Group correlated variants by source/attack lineage and keep those groups across split boundaries; repeating a payload is not fresh independent evidence.

## Open evaluation

Public benchmarks already exist: [AgentDojo](https://github.com/ethz-spylab/agentdojo), [InjecAgent](https://aclanthology.org/2024.findings-acl.624/), and [BIPIA](https://github.com/microsoft/BIPIA). Their tasks are not interchangeable with our policy-driven classifier tests. Integrations need explicit mappings, licenses, preserved labels and separate task-success metrics.

Our design recommendation: publish policy components, harnesses, development cases and complete bounded-run records; maintain unseen evaluation cases and periodically refresh them. Explicitly test policy-aware adaptive attacks. Keep held-out cases out of policy advice, examples and tuning. Report contamination risk and whether a result is development, held-out or third-party replication. Public policies enable scrutiny but also adaptive attacks; private weights do not prevent black-box probing. No static public score certifies safety in every application.

## Tracked next steps, not shipped capabilities

- Add a versioned model-neutral policy representation and capability checks at rendering boundaries, preserving Jev native evaluation as a distinct arm.
- Add a supported OpenAI-compatible/local-model adapter with strict response schemas and explicit local runtime provenance. Extend the existing CLI runner instead of building a second orchestration system.
- Let users choose supported models independently for policy advice, coverage advice and evaluation.
- Standardize optional cost/performance metadata in portable uploads and build comparisons only between compatible tasks/contracts.
- Support composable policy-component revisions and GitHub PR review with regression evidence; provider-authenticated receipts remain separate work.
- Consider `redteam-observatory` branding/address when Sites supports a safe URL migration. The available title-update operation does not rename the URL. Keep the current site identity, saved runs and existing links intact meanwhile.
