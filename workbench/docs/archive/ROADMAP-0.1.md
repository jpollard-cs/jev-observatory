# Product scope and next validation gates

## Shipped: coherent local vertical slice

Configure → explain → compile → plan → freeze → explicitly run → inspect → export. No mock “Run” button, no fabricated inference results. A simulated transport exists only in software tests.

## Gate 1: user-specific policy validation

Allow reviewed custom scenario packs against a declared task schema, with label provenance, contrast groups and explicit non-applicability. Do not advertise arbitrary natural-language policy validation by merely replaying the existing incident cases. A future assistant may suggest policy modules, but the consumer must review the structured diff.

## Gate 2: stronger contextual evidence

Expand the three authored dossiers into longer, varied, licensed or user-approved documents; preserve the actual task requirement and source provenance. Vary position and source sequence, multi-step composition, competing legitimate directives and repeated/adaptive adversarial behavior. Report material size, provider tokens and source count separately. Add a real downstream task runner only under explicit sandbox and effect constraints.

## Gate 3: selection research

Compare the present mandatory/seeded coverage planner with Jev-assisted taxonomy tagging. Freeze independent audit samples and mandatory probes so a model cannot silently select away its own weaknesses. Cache corpus annotations by content hash; keep no-result/unknown categories. Categories forbidden by a policy still require rejection tests. Preserve associated fragments as one semantic scenario.

## Gate 4: broader usability and interpretation

Obtain ordinary production-like benign samples with consent; separate them from adversarially constructed hard negatives. Review multilingual annotations with speakers/domain experts. Report confidence intervals only where the independence/sampling assumptions are defensible. Do not turn Gold into a security grade.

## Gate 5: sharing and hosted integration

Keep the initial interface local-first. Before public uploads: explicit opt-in, credential/content scanning, data licensing, private/public policy decisions, storage threat model, abuse controls and visibility into all selected outcomes. Distinguish self-reported, reproducible and independently rerun evidence. Preserve hashes without pretending that a checksum proves a provider executed the request.

No work is scheduled or running in the background by this document.
